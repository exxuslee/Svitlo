# Архитектура приложения

Приложение состоит из трёх модулей. `domain` содержит модели, интерфейсы
репозиториев и юзкейсы; `data` реализует доступ к сети и Room; `app` отвечает
за Compose, ViewModel, виджеты и Android-уведомления. `domain` не зависит
от Android. Связывание реализаций выполняют модули Koin.

## Загрузка расписаний

`RegionCatalog` определяет источник региона. `ScheduleRemoteDataSource`
проверяет конфигурацию источника, вызывает Yasno или GitHub JSON и декодирует
ответ соответствующим маппером. Результат `SchedulePayload` предоставляет
список групп и преобразование выбранной группы в `OutageSchedule`.

`LocationRepositoryImpl` использует этот результат для получения групп.
`ScheduleRepositoryImpl` делегирует обновления внутреннему `ScheduleRefresher`,
который преобразует ответ в расписание и сохраняет в Room. Один экземпляр
компонента на репозиторий сериализует загрузку и запись внутри региона,
ограничивает число одновременно обновляемых регионов тремя и загружает
каждый регион один раз на пакет. Ошибка отдельной группы не мешает
сохранению остальных; отмена освобождает блокировки и распространяется выше.
Наблюдение за расписаниями всегда читает кэш; неудачное обновление оставляет
его содержимое прежним. Отмена корутины распространяется вызывающему коду,
а обычные ошибки обновления возвращаются как `Result.failure`.

## Наблюдение за адресами

`ObservePlaceSchedules` объединяет сохранённые адреса с их расписаниями
в список `PlaceSchedule`. Он сохраняет порядок адресов, допускает отсутствие
расписания и отменяет прежние подписки при изменении списка адресов.
Пустому списку адресов соответствует пустой список результатов.

`HomeViewModel` использует одну такую подписку. Изменение адресов запускает
обновление данных, а изменение только расписания обновляет карточки.
`NotificationCoordinator` использует тот же юзкейс для перепланирования
напоминаний.

## Уведомления

`NotificationPlanner` рассчитывает напоминания без Android API: учитывает
опубликованные дни, интервалы отключений, время напоминания и тихие часы
с 23:00 до 07:00 по времени Киева. Тихие часы проверяются по моменту
напоминания. Прошедшие напоминания исключаются. Часы передаются явно,
поэтому расчёт воспроизводится в unit-тестах.

`NotificationScheduler` применяет результат через `AlarmManager`, создаёт
`PendingIntent` и отменяет лишние будильники. Идентификаторы и параметры
существующих будильников сохраняют прежний формат.

## Обновления приложения

`MainActivity` проверяет доступность новой версии через `PlayAppUpdater`
при создании. Google Play предлагает необязательное обновление типа FLEXIBLE:
после согласия загрузка идёт в фоне, а Compose Snackbar предлагает установку
с перезапуском. При возвращении в приложение повторно проверяется наличие
уже скачанного обновления. Слушатель загрузки освобождается при уничтожении
Activity; ошибки Play не препятствуют использованию приложения.

Для проверки через Google Play нужна установленная из Play версия и доступная
этому аккаунту публикация с большим `versionCode` и той же подписью.
Локальная debug-сборка проверяет компиляцию интеграции, но не показ окна Play.

## Проверка

```powershell
.\gradlew.bat :domain:test :data:testDebugUnitTest :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

Тесты проверяют оба формата источников, сохранение кэша при ошибках,
распространение отмены, обновление и удаление адресов, отсутствие повторного
обновления при изменении расписания и расчёт напоминаний на границах суток
и тихих часов. Тесты ViewModel освобождают её до завершения тестовой корутины,
чтобы таймер обновления карточек не оставался активным.

## Состояние экранов и действия

Состояние экрана читается через `collectAsStateWithLifecycle`. Одноразовые
действия ViewModel передаются через буферизированный `Channel`; единственный
потребитель экрана — `ObserveActions` — обрабатывает их в `LaunchedEffect`
при состоянии `RESUMED`. Во время паузы новые действия ожидают обработки,
а уже полученные не повторяются при новой подписке. Очередь живёт вместе
с ViewModel и не сохраняется при завершении процесса; это не механизм
гарантированной доставки важных бизнес-операций.

## Фоновые задачи и зависимости

`useCaseModule` регистрирует сценарии, `presentationModule` — ViewModel,
`platformModule` — часы, версию приложения, общий scope приложения и
Android-сервисы. `WidgetCoordinator` и `NotificationCoordinator` получают
зависимости через конструкторы; повторный запуск не создаёт новые подписки.
Канал уведомлений создаётся при запуске координатора уведомлений.

`ScheduleRefreshScheduler` планирует общее обновление графиков каждые
30 минут при доступной сети независимо от наличия виджетов.
`ScheduleRefreshWorker` обновляет графики, виджеты и напоминания.
При полном или частичном сбое загрузки Worker применяет доступные данные
из кэша и запрашивает повтор через WorkManager. Один периодический запуск
ограничен тремя попытками; после третьего сбоя возвращается failure,
следующий периодический запуск остаётся запланированным.
`NotificationScheduler` получает Context и Clock через DI; координатор
и Worker используют один экземпляр. Применение будильников сериализовано.
`App` предоставляет WorkManager конфигурацию с `ScheduleWorkerFactory`;
стандартный Startup-инициализатор WorkManager отключён в манифесте.
Имя уникальной работы сохранено, а фабрика поддерживает прежнее имя
`WidgetRefreshWorker`, чтобы обновление приложения не сломало очередь.
Для остальных работников, включая Glance, остаётся стандартная фабрика.

Общие цвета экранов находятся в `ui.theme.AppColors`: базовые цвета
читаются из `MaterialTheme.colorScheme`, дополнительные роли определены
в одном месте. Сценарии domain сгруппированы по местам, географии,
графикам и теме без изменения их публичных имён.

`AddressViewModel` отменяет предыдущую загрузку групп при смене поставщика
или области. Отменённый запрос не меняет состояние даже при позднем ответе
источника; CancellationException распространяется при загрузке и сохранении.
Восстановление адреса при обычной ошибке загрузки групп сохраняет выбранную
группу из адреса. Общая подпись группы для карточки и виджета находится
в `ui.common.groupLabel`.

## Общие элементы карточки и виджета

`ui.schedule` содержит общую модель `ScheduleCardUi`, её mapper, палитру
и представление часовых ячеек `ScheduleTimeline`. За основу взята карточка
главного экрана: цвета состояний, зелёная рамка текущего часа, размеры ячеек
и контраст подписей определяются здесь для обоих вариантов отображения.
`PlaceCardMapper` сохраняет интерфейс экрана и делегирует общему mapper;
`ScheduleWidgetMapper` использует его же, включая проверку `published`.
Неопубликованный сегодняшний график отображается неизвестными состояниями
без маркера; неопубликованный завтрашний — сообщением о недоступности.

`ScheduleElements` и `GlanceScheduleElements` — адаптеры общих элементов
для Compose и Glance/RemoteViews. Glance не может исполнять UI-компоненты
Compose; адаптеры используют одни данные, палитру и параметры графика.
Виджет использует тёмную палитру для читаемости на стеклянном фоне.
Переключение дней остаётся через `WidgetDayReceiver`: обе страницы передаются
лаунчеру сразу, нажатие меняет видимость без пересоздания графика.
