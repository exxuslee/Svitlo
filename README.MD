# Світло · Svitlo

Android-застосунок для перегляду графіків відключень електроенергії в Україні. Зберігайте потрібні місця, стежте за розкладом на сьогодні й завтра та отримуйте нагадування перед відключенням. Інтерфейс застосунку — українською мовою.

## Можливості

- Кілька збережених місць із вибором регіону, постачальника електроенергії та групи відключень, власною назвою та піктограмою.
- Графіки з півгодинними інтервалами на сьогодні й завтра, позначкою поточного часу та часом оновлення даних.
- Редагування та видалення збережених місць.
- Нагадування перед відключеннями та режим «Не турбувати вночі» з 23:00 до 07:00.
- Віджет головного екрана з перемиканням між графіками на сьогодні й завтра.
- Світла й темна теми.
- Локальний кеш розкладів: у разі помилки мережі раніше завантажені дані зберігаються.
- Фонове оновлення через WorkManager з інтервалом 30 хвилин за наявності мережі. Фактичний час запуску залежить від обмежень Android.

Розклади та нагадування розраховуються за київським часом (`Europe/Kyiv`). Графік на завтра відображається після його публікації джерелом. Застосунок показує опубліковані дані; фактичне електропостачання, зокрема під час аварійних відключень, може відрізнятися від графіка.

## Джерела та регіони

Каталог регіонів і постачальників міститься в [`data/src/main/assets/regions.json`](data/src/main/assets/regions.json). У поточному каталозі є Київ та області: Київська, Вінницька, Дніпропетровська, Житомирська, Закарпатська, Запорізька, Івано-Франківська, Львівська, Одеська, Полтавська, Рівненська, Тернопільська, Хмельницька та Чернігівська.

Застосунок отримує дані безпосередньо з двох типів джерел:

- Публічний API YASNO — для Києва та постачальників Дніпропетровської області, зазначених у каталозі.
- JSON-файли з репозиторіїв [Baskerville42/outage-data-ua](https://github.com/Baskerville42/outage-data-ua), [olnet93/gpv-voe-vinnytsia](https://github.com/olnet93/gpv-voe-vinnytsia) та [yaroslav2901/OE_OUTAGE_DATA](https://github.com/yaroslav2901/OE_OUTAGE_DATA).

Доступність і актуальність розкладів залежать від зовнішніх джерел. Для отримання нових даних потрібен інтернет; збережений кеш може застаріти. Для локальної debug-збірки власний сервер та API-ключі не потрібні.

## Технології та структура

Проєкт використовує Kotlin, Jetpack Compose і Material 3, Navigation Compose, Coroutines і Flow, Koin, Ktor з OkHttp, Kotlin Serialization, Room, DataStore, Glance та WorkManager. Версії залежностей задано в [`gradle/libs.versions.toml`](gradle/libs.versions.toml).

| Модуль | Призначення |
| --- | --- |
| `app` | Android-застосунок: екрани Compose, ViewModel, навігація, віджет, сповіщення та фонові завдання |
| `domain` | Моделі, інтерфейси репозиторіїв і сценарії використання; Kotlin/JVM без залежності від Android |
| `data` | Завантаження та перетворення даних, каталог регіонів, репозиторії та локальна база Room |
| `docs` | Опис архітектури та випуску релізів |

`app` залежить від `domain` і `data`, а `data` — від `domain`. Реалізації зв’язуються через Koin. Докладніше — у [`docs/architecture.md`](docs/architecture.md).

## Підготовка середовища

1. Установіть Android Studio з підтримкою використаного Android Gradle Plugin (версію зазначено в каталозі залежностей).
2. Установіть Android SDK Platform 37 та Android SDK Platform-Tools через SDK Manager.
3. Підготуйте JDK 25 для Gradle daemon: цю версію закріплено в [`gradle/gradle-daemon-jvm.properties`](gradle/gradle-daemon-jvm.properties). Цільова версія Java/Kotlin-байткоду модулів — 11.
4. Відкрийте корінь проєкту в Android Studio та виконайте Gradle Sync. Використовуйте Gradle Wrapper із репозиторію.
5. Укажіть шлях до Android SDK у локальному файлі `local.properties`, якщо IDE не створила його автоматично:

   ```properties
   # Приклад для Windows; замініть шлях на власний.
   sdk.dir=C:/Users/user/AppData/Local/Android/Sdk
   ```

`local.properties` виключено з Git. Перший запуск Gradle потребує доступу до репозиторіїв залежностей і, у разі автоматичного отримання JDK, до сервісу завантаження toolchain.

Мінімальна версія Android для пристрою або емулятора — **Android 9 (API 28)**. `compileSdk` і `targetSdk` — **37**. Ідентифікатор застосунку — `org.exxlexxlee.svitlo`.

## Збирання та запуск

Команди виконуються з кореня проєкту. Для Windows PowerShell:

```powershell
# Зібрати debug APK
.\gradlew.bat :app:assembleDebug

# Установити на підключений пристрій або запущений емулятор
.\gradlew.bat :app:installDebug
```

Debug APK з’явиться в `app/build/outputs/apk/debug/app-debug.apk`. Після встановлення відкрийте «Світло» на пристрої або запустіть конфігурацію модуля `app` з Android Studio.

Для Linux/macOS використовуйте `./gradlew` замість `.\gradlew.bat`; за потреби спочатку виконайте `chmod +x gradlew`.

Під час першого використання додайте місце: виберіть регіон, постачальника, групу відключень і задайте назву та параметри нагадувань. Для сповіщень на Android 13+ потрібен дозвіл на їх показ. За відсутності дозволу на точні будильники застосунок використовує неточне планування, тому нагадування може надійти із затримкою. Віджет додається через меню віджетів лаунчера після налаштування місця в застосунку.

## Перевірки

До застосунку підключено Firebase Crashlytics, Analytics та Cloud Messaging.
Налаштування, перевірка доставки й вимоги перед публікацією описані в
[`docs/firebase.md`](docs/firebase.md).

Модульні тести всіх трьох модулів:

```powershell
.\gradlew.bat :domain:test :data:testDebugUnitTest :app:testDebugUnitTest
```

Збирання та статичний аналіз Android-застосунку:

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug
```

Інструментальні тести потребують підключеного пристрою або запущеного емулятора:

```powershell
.\gradlew.bat :data:connectedDebugAndroidTest :app:connectedDebugAndroidTest
```

У репозиторії є тести перетворення даних джерел, кешування розкладів, розрахунку інтервалів і нагадувань, ViewModel та віджета. Workflow [`CI`](.github/workflows/ci.yml) під час push і pull request запускає модульні тести, збирає debug та оптимізований release з R8.

## Релізи та Google Play

Автоматичну публікацію налаштовано в [`.github/workflows/release.yml`](.github/workflows/release.yml). Надсилання тега `vX.X.X` запускає перевірки, збирання підписаного AAB і надсилання в **production Google Play**. Вимоги до секретів, правила версій і повторний запуск описано в [`docs/releases.md`](docs/releases.md).

Для локального release AAB:

```powershell
.\gradlew.bat :app:bundleRelease -PreleaseVersionName=1.3.1 -PreleaseVersionCode=1003001
```

Параметри `releaseVersionName` і `releaseVersionCode` передаються разом. Для підписування задайте всі чотири змінні середовища: `ANDROID_KEYSTORE_PATH` (бажано абсолютний шлях), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` та `ANDROID_KEY_PASSWORD`. Без них release-збірка залишається непідписаною. Ключі та паролі не додавайте до репозиторію.
